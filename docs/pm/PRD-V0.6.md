## 1. 战略判断：V0.5 之后剩下的三处缺口

V0.5 让结构语义贯通、让产出可带走、让资产可见可信。把产品再当作「每天用的论文阅读器」审视，剩下的是三处**日常触感**上的缺口：

1. **笔记与原文在空间上失联。** 笔记有了页码锚点、能跳回，但**在 PDF 页面上看不见**：读到第 7 页时，没有任何线索告诉你「这一页你摘过两句话」，更看不到「摘的是哪一句」。用户只能靠打开左栏逐条比对。笔记必须回到它诞生的位置上。
2. **能力存在但不可发现。** 章节导航 `[` `]`、翻页、`/`、Ctrl+F、摘录、问 AI 都已可用，但界面不告诉用户；选中一段英文后，最常用的两个动作（解释、翻译）需要用户自己组织问法。效率与可发现性应当被显式设计，而不是靠用户摸索。
3. **对话与文档没有绑定关系。** 「我上周读过这篇，还聊过几轮」这件事系统不知道：会话按工作区隔离，读某篇论文时找不到当时那段讨论。文档应当记住自己的阅读与讨论历史。

**V0.6 主题：读得到、找得到、接得上。**
让笔记在原文页面上可见可点（R16），让既有能力可发现、常用动作一步可达（R17），让文档记得自己的对话（R18）；再用规模与性能一轮，把大文档与大量笔记下的体验钉住（R19），最后以一轮全量审查与收口结束（R20）。

## 2. 迭代路线（R16–R20）

| 迭代 | 名称 | 一句话 | 依赖 | 性质 |
| --- | --- | --- | --- | --- |
| R16 | 原文锚点 | 每页可见笔记标记；当前页的摘录文本若能在文字层匹配则以独立高亮标出（best-effort，失败静默降级）；标记可定位到笔记面板 | R7、R9、R13 | 功能 |
| R17 | 操作可达性 | 快捷键总览浮层；选区模板动作（解释 / 翻译 → 只预填草稿，不自动发送） | — | 体验 |
| R18 | 对话锚定 | 阅读现场记住每篇文档的最近会话；提供「继续讨论这篇论文」入口；会话列表标注关联文档 | R6、R10 | 功能 |
| R19 | 规模与性能 | 大文档（≥300 页）与大量笔记（≥500 条）下的打开、翻页、搜索、面板与报告的实测与修复 | R13、R16 | 质量 |
| R20 | 全量审查与收口 | 全仓库审查（增量优先）+ 修复 + 文档与 README 收口 + 版本验收 | R16–R19 | 质量 |

依赖是真实的：R16 复用 R13 报告的章节/页锚点语义与 R9 的地图派生；R18 复用 R6 的 `.pix-read/reader-state.json` 现场数据（新增字段必须是易失状态口径）；R19 的夹具与判据依赖 R16 的高亮与 R13 的报告在大规模下的表现；R20 必须在 R16–R19 全部落地后执行。

## 4. 版本级反需求（跨迭代写死）

1. 不做论文下载、元数据抓取、DOI/引用解析、云同步、多设备。
2. 不做 LLM 自动摘要 / 自动写笔记 / 自动打标签；**R17 的模板动作只允许预填 composer 草稿，绝不自动发送**。
3. 不做向量检索、全文索引服务、知识图谱、双链、标签体系。
4. 不做多标签、多文档对比、暗色主题、多色笔、压感、公式识别、OCR；R16 的高亮只用文字层做 best-effort 匹配，**不做 OCR、不做跨页文本重建**。
5. 不引入新运行时依赖（含 d3 / markmap / fuse / 虚拟滚动库）；不改 `packages/*`；不改 electron-builder 配置。
6. 不改 `.pix-read/notes.json` 的格式与写入协议；`.pix-read/` 之外的仓库内容不被产品写入。
7. 不做向后兼容层；不写未被调用的死代码；不为「看起来高级」加动画。
8. R16 的页面标记与高亮**不得**改变 PDF 文字层 DOM 结构、不得拦截文本选择与既有搜索高亮（`::highlight(pix-search)`）。

## 5. 工程红线（对每一轮的子代理生效）

沿用 `PRD-V0.5.md` §5 全部条款（工程门、禁 any/内联动态 import、UI 文案中文、子代理禁 git 写命令与 build/test/package/dev、IPC 入参校验、原子写、取证纪律、零依赖改动、离屏串行、临时产物零残留），另加：

1. 每轮动工前跑基线离屏取证，收工后跑验收取证；`MANIFEST.json.failure === null`、退出码 0、既有场景与断言零缺失；基线与验收目录按 `pix-v05-r<N>-*` 命名沿用（临时目录）。
2. 新增/变更的 UI 与交互必须有离屏场景与断言；冻结字面的有意变更必须在本轮需求档显式登记（改哪一条、为什么、旧断言如何更新）。
3. 性能类判据必须给出**可复跑的测量方式与阈值**（探针脚本写 `%TEMP%` 或固化为仓库内脚本），不得只给「感觉更快」。

## 6. 每轮流水线（对子代理可见的执行契约）

```
需求(PM) → 需求评审(挑刺) → 需求定稿 → 设计(架构) → 设计评审(挑刺) → 设计定稿
   → 开发(契约面 → UI 面) → 独立审查(冷启动, 复跑全部验证) → 修复 → 终验 → 负责人提交
```

- 评审必须给 must-fix 清单；must-fix 未销账不得提交；拒绝 must-fix 必须写明技术理由并由负责人在档件中追认。
- 每轮开发档必须包含：改动清单、真实命令与原样输出摘要、逐条自评、偏差表、未验证事项。

## 7. 版本成功判据

1. **原文锚点可用**：任意一页能看出「本页有几条笔记」；当前页的摘录在文字层可匹配时高亮、不可匹配时静默；标记点击能到达对应笔记，且不与既有过滤/跳转打架；选择、搜索与翻页行为零回归。
2. **能力可发现**：存在一处可发现、可关闭、可键盘操作的快捷键总览；选区模板动作只预填草稿（可编辑、可清除、不自动发送）。
3. **对话接得上**：打开一篇读过的文档时，能一步回到上次讨论的会话；会话列表能看出与哪篇文档相关；旧 `reader-state.json` 零报错兼容。
4. **规模不塌**：300 页文档与 500 条笔记下，打开、翻页、搜索、面板渲染与报告导出有实测数据且不出现 >1s 的无反馈卡顿（阈值与测量方式在 R19 需求档冻结）。
5. **收口干净**：R20 的全量审查清单全部有结论（修复或登记不修 + 理由）；`packages/*` 与依赖零改动；README 与实现一致；每轮 `npm run check` 0 error。
