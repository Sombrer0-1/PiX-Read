# PiX-Read V0.4 产品需求文档（负责人：主 agent / 迭代负责人）

> 上游：`docs/pm/PRD-V0.3.md`（N17–N25 已交付：选中即摘录 → 左栏笔记面板 → 点击跳回原文 → 导出 Markdown；`<工作区根>/.pix-read/notes.json` 为唯一事实源，主进程唯一写者 + 原子写 + 损坏不覆盖）。

## 1. 战略判断：V0.3 之后暴露的三处断层

V0.2 解决「读得进」，V0.3 解决「读有所得」（摘录沉淀、回跳、外带）。交付之后，把产品当作**每天要用的本机阅读器**重新审视，剩下的不是功能数量问题，而是三处结构性断层：

1. **现场不恢复（记忆缺失）**
   阅读器每次打开都从第 1 页、缩放 1.0 开始；资料库看不出哪篇读到一半；「我昨天读到 12 页」这件事系统完全不知道。对「本机论文阅读器」，这是最刺眼的日常断层——它让每一次阅读都是重新开始。

2. **结论不沉淀（半截资产）**
   用户真正拿到的价值有一半在对话里：一段解释、一次梳理、一个对比。V0.3 只把「用户选中的原文」沉淀下来。AI 结论仍然只存在于会话中——而会话是可被压缩、切换、丢弃的容器。V0.3 已为此冻结了 `kind: "answer"` 字段，本轮把它落地。

3. **资产不复用（死数据）**
   笔记看得到、跳得回，却喂不回给 agent。「把我这 5 条摘录放一起对比」「就这一条继续追问」这类最自然的动作，今天只能靠手动复制粘贴。笔记作为资产的价值，取决于它能否被再次消费。

**V0.4 主题：读得回、用得上。** 让阅读现场可恢复、让 AI 结论可入库、让笔记重新成为 agent 的上下文，并把这三种东西挂回论文自身的结构（章节树）。

## 2. 迭代路线（R6–R10）

| 迭代 | 名称 | 一句话 | 依赖 | 性质 |
| --- | --- | --- | --- | --- |
| R6 | 阅读现场 | 每篇文档的阅读位置与缩放随工作区持久化，重开应用可续读；资料库树可见进度 | — | 体验基建 |
| R7 | 结论入库 | AI 回答一键存为笔记（`kind=answer`），与摘录同组、可跳回、可导出 | R6 | 功能 |
| R8 | 资产复用 | 笔记多选显式注入对话上下文；单条可追问 | R7 | 功能 |
| R9 | 结构联动 | 知识地图显示各章笔记数与阅读进度（视觉迭代） | R6、R7 | 视觉 |
| R10 | 规模可用 | 笔记搜索、排序、撤销删除、单条复制 | R7、R8 | 打磨 |

依赖是真实的：R7 的「AI 结论」需要锚点（发送时的文档 + 页码），而锚点的落页语义由 R6 建立的现场恢复复用；R9 的「章节笔记数」同时依赖 R6 的进度与 R7 的两类笔记；R10 的搜索与撤销要在两类笔记都存在之后才有意义。

## 3. 资产分层（本版本写死）

| 路径 | 性质 | 损坏时的行为 |
| --- | --- | --- |
| `<工作区根>/.pix-read/notes.json` | **用户资产**（事实源） | 报错、绝不覆盖、用户显式决策（既有逃生口） |
| `<工作区根>/.pix-read/notes.md` | 导出产物 | 全量覆盖写 |
| `<工作区根>/.pix-read/reader-state.json` | **易失状态**（现场记忆，R6 新增） | 静默降级为空状态并允许重建；绝不阻塞阅读链路 |

一句话原则：**资产宁可停下来问用户，状态宁可自己重来。** 这条区分决定了 reader-state 不允许出现错误面板、不允许阻塞打开文档、不允许把用户卡在恢复流程里。

## 4. 版本级反需求（跨迭代写死）

1. 不自动打开上次文档、不做启动即跳页（现场恢复只提供**显式入口**，不劫持启动流程）。
2. 不做阅读时长统计、打卡、阅读目标、成就。
3. 不做「AI 自动写笔记」：笔记只能由用户的显式动作产生（选中摘录、点击存为笔记）；不给 agent 写笔记的工具。
4. 不做笔记静默注入：任何进入上下文的内容必须在 composer chips 上可见、可移除；不做「总是包含全部笔记」。
5. 不做跨工作区聚合、云同步、多设备；所有资产留在当前工作区 `.pix-read/`。
6. 不做笔记全文索引服务、不做向量检索、不做自动标签/双链/知识图谱。
7. 不引入新依赖（含 d3 / markmap / fuse 等），不为了「看起来高级」加动画。
8. 不做暗色主题、多标签、多文档对比、论文下载、元数据抓取。
9. 不改 `packages/*`（pi 内核），不改 `electron-builder` 配置，不新增运行时依赖。

## 5. 工程红线（对每一轮的子代理生效）

1. `cd pix && npm run check`（vue-tsc + 主进程 tsc + preload tsc）必须 **0 error**，这是唯一工程门。
2. 禁止 `any`；禁止内联动态 import（`await import()` / `import("x").T`），全部顶层 import。
3. UI 文案中文；注释只写约束、不写流水账；风格向同文件看齐；Vuetify 用法照抄仓库内既有写法（本仓库无 `vuetify_guide/` 目录）。
4. 不运行 `npm run build` / `npm test` / `npm run package` / `npm run dev`；不执行任何 git 写命令（`git status` / `git diff` / `git show` 只读可用）。提交由负责人（主 agent）在流水线末端完成。
5. 主进程新增 IPC 必须有入参校验与中文错误；渲染层失败路径不得静默；渲染层不得自行拼接存储路径（路径一律由主进程从资料库根派生）。
6. 不做向后兼容层；不写未被调用的死代码；不越出本轮文件白名单。
7. `pix/scripts/ui-shot.mjs` 是既有的离屏截图取证脚本：**本迭代新增/变更的 UI 必须有对应场景与截图产出**（stub 的 `pixApi` 面必须与 `preload.ts` 保持一致）；无法在 stub 下构造的 UI 允许降级为代码级核对，但必须在开发档里写明。

## 6. 每轮流水线（对子代理可见的执行契约）

```
需求(PM) → 需求评审(挑刺) → 设计(架构) → 设计评审(挑刺) → 设计定稿 → 开发(契约面 → UI 面) → 代码审查+验收 → 修复 → 终验(check + ui-shot + 越界核对) → 负责人提交
```

- 需求档：`docs/pm/R<n>-req.md`（需求编号、用户可见行为、逐条验收标准、反需求、文件范围）
- 评审档：`docs/pm/R<n>-review.md`（需求评审与设计评审的 must-fix 追加记录）
- 设计档：`docs/pm/R<n>-design.md`（契约、文件级清单、时序/状态机、失败路径、must-fix 处理表、验证方案）
- 开发档：`docs/pm/R<n>-dev.md`（改动清单、真实执行的命令与结果、逐条自评、未验证事项）

## 7. 版本成功判据

1. **现场可恢复**：关掉应用 → 重开同一工作区 → 打开文档落在上次页码与缩放；资料库树能看出进度；状态文件损坏只降级、不报错、不阻塞。
2. **结论可沉淀**：对话里的一条回答能变成笔记，带文档与页码锚点，能跳回原文、能备注、能导出，与摘录互不混淆、互不覆盖。
3. **资产可复用**：把若干条笔记放进一次提问的上下文，全程可见可移除；对单条笔记可以直接追问。
4. **结构可见**：知识地图上能看出「这一章我读了多少、摘了几条」。
5. **规模可用**：笔记到几十条时仍能检索、排序、撤销误删、单条复制。
6. **零外溢**：`packages/*` 与本轮文件白名单之外零改动；`npm run check` 每轮 0 error。

### 8.2 成功判据复核（§7）

1. **现场可恢复**：达成。打开文档落上次页码与缩放；空态「继续阅读」；树进度徽标；`reader-state.json` 损坏/缺失/版本不符一律静默降级并允许重建（R6 终验含 41 项数据面断言）。
2. **结论可沉淀**：达成。回答可存为笔记并带发送时刻锚点；面板与导出区分两类内容；同文本的摘录与结论并存（R7 终验含 51 项字节级断言）。
3. **资产可复用**：达成。多选注入全程可见可移除、有硬上限与超限提示；单条追问保留草稿并聚焦（R8 终验 21 组注入文本断言，含与 R7 逐字节相同的回归用例）。
4. **结构可见**：达成。地图徽标 ≡ 点它后可见行数（R9 以变异对照验证过该恒等式）；进度与已读弱化落地，无既有画面布局位移。
5. **规模可用**：达成。搜索/排序/撤销/复制齐备；撤销是真实反写，任何时刻「面板所见即文件所存」（R10 终验 76 项独立断言 + 文件字节回复）。
6. **零外溢**：达成。`packages/*` 五轮零改动；白名单外零改动；每轮 `npm run check` 0 error。

### 8.3 遗留事项（记录，不阻塞版本）

- **只在代码审查面成立、缺离屏相位的条目**：恢复侧越界钳制、非 PDF 锚点恒第 1 页、steer 轮锚点、错误态下的地图徽标、过滤态下的导出与跳回原文。
- **人工走查项**：翻页后 1 秒内真实关窗再重开的续读（`visibilitychange/pagehide` 事件路径已被离屏覆盖，真实关窗未覆盖）。
- **取证脚本自身**：`pix/scripts/ui-shot.mjs` 运行成功时不清空 `shots/` 旧文件，历史失败残留的 `99-failure-state.png` 会与新产物混在一起（建议下一轮加启动清理）。
- **性能**：会话块索引化后帧内解析已收敛（实测大列表快两个量级），但未做真实帧率测量；`countNotesByChapter` 对 ranges 两次线性遍历（复杂度仍 O(n+m)）。
- **未落仓库的烟测脚本**：按设计纪律只在 `%TEMP%` 运行并删除，因此不可被第三方复跑；未来可考虑把关键数据面烟测纳入仓库内的测试入口。
